为什么银行需要AI 可观测？

传统 APM 只覆盖基础设施层，无法洞察 AI 助手的核心行为与业务语义。

❌ 传统可观测的三大盲区
1

只覆盖基础设施层

JVM/HTTP/DB 指标齐全，但看不到 LLM 行为：Token 消耗、首字延时(TTFT)、意图准确率、路由决策、会话满意度——这些才是 AI 助手的 KPI。

2

无法回答「为什么」

传统监控告诉你「LLM 错误率 ↑」，但不知道根因在哪：是 Prompt 太长？外部 API 超时？还是某个意图域模型能力不足？只能人工翻日志盲猜。

3

故障靠人工发现

没有自动告警和根因定位：LLM 404 挂了一整天全靠客户投诉才知道；慢请求堆积无人感知；合规风险无法主动预警。

✅ 银行 AI 助手四大核心需求
①

全链路透明可视

从用户输入 → DomainRouter 路由 → LLM 推理 → Agent 执行 → 最终响应，完整调用链路一屏尽览。每一步耗时、Token 用量、置信度清晰可见。

②

从「是什么」升级为「为什么 + 怎么办」

不只是看指标趋势，更要自动根因定位 + 优先级行动建议。慢会话？自动追溯 Span 级瓶颈并给出优化方向。

③

金融级合规与安全

字段级数据脱敏(卡号/身份证/手机号)、五角色 RBAC 访问控制、TLS 全链路加密、审计日志——满足银保监合规要求。

④

千万级规模支撑

日均 500~1500 万次 AI 交互、2000~6000 万 Span/天、9~27 亿行 Session/半年。PostgreSQL 分区表 + Redis Sentinel + TDigest 流式分位，扛住银行量级。

会话回放 & 链路追踪 —— 完整还原每次对话

💬 会话回放 Session Replay

  • ▸ 逐轮对话完整记录：userMessage / aiResponse / intent / confidence / durationMs / tokens
  • ▸ 分层意图链：L0(DomainRouter) → L1(ContextRouter) → L2(BusinessAgent) 三层意图一目了然
  • ▸ 三件套联动跳转： traceId→链路 sessionId→会话 logId→日志
  • ▸ 满意度反馈：每轮可标记满意/不满意，聚类共性问题
  • ▸ 数据独立管道：@Async fire-and-forget 上报，不依赖 Trace 成败

🔗 链路追踪 Trace Tracking

  • ▸ L0 → L1 → L2 瀑布图：三层 Agent 调用时序可视化，每层耗时清晰
  • ▸ 关键字段全覆盖：TTFT / Token 总量 / duration / status / llm.confidence / intent 预测&实际值
  • ▸ Agents 链显示：确定性路由(L0:DomainRouter)与 LLM 路由(L0:qwen-plus)并列渲染
  • ▸ IO 面板：prompt / response 原文查看（已脱敏）
  • ▸ 按 traceId 去重枚举：跳过无业务 span 的噪声 trace
