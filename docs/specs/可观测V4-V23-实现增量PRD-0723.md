## 0. 本期范围判定（关键事实，直接采用）

- **V23 真·新增仅 2 个前端埋点**：`mbank_card_click`（业务引导办理次数）、`mbank_human_click`（转人工次数）→ 需新建 `business_events` 表 + `POST /api/v1/business-events` + `BusinessEventQueryService`；外加 1 项轻量：MCP per-tool 需 Core 给调用打 `category=mcp` tag。
- **演示稿标"待接入"的 4 项实为已连线**（重路由比率 / 业务完成率 / 意图识别综合正确率 L0-L1 / 意图改写正确率 L1），本期**只在 UI 上"显式分层 / 改名 / 统一口径"**，**不新增后端管线**。
- **W3 遗留本期做**：L1（B-A，方案A，前端 0.3 人日）、L4（start-all.ps1 编译段，DevOps 0.2 人日）。B-B/B-C 经代码核对已定性非 BUG/已闭环，本期**不做**。
- **M 系列建议实现顺序**：M1/M2 埋点 → M3 聚合入库 → M6 看板/总览 UI → M4/M5 洞察（条件触发区 + 外部调用 TAB）→ M10 MCP；M11 RAG 体量最大、依赖最多，排最后或本期可选。
- **总盘子**：V23 M 系列 ≈14 人日（排期 §⑥.2 角色口径；任务粒度 §⑥.1 合计 12.0，差额为前端并行余量，见附录 A）+ W3 遗留 BUG ≈0.5 人日（L1 0.3 + L4 0.2）。
