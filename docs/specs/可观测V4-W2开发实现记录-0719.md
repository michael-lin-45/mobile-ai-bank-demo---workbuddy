## 1. 任务背景

- **ADR-2026-07-19 裁定**：遥测唯一主线是 OTLP Push，`/actuator/prometheus` 端点为 out-of-design、待回退（任务 I-1~I-4）。
- 早前交付运行已实现《可观测V4-详细设计-0719.md》全部任务（T-A~T-N）与 RAG 埋点层（T01~T04）。
- W2 收尾首轮仅改 Backend yml 一处（I-2 Backend 侧）。后续经 team-lead 裁定，两个 Core profile 子配置（`application -商 .yml`、`application -阿里.yml`）亦属 I-2 回退范围（此前遗漏），本轮一并收口。
- **GAP-M2（本轮补做）**：交叉核验发现 Backend 子模块 `pom.xml` 仍含 `micrometer-registry-prometheus` 依赖（L49-53）——它是 `/actuator/prometheus` 端点能被暴露的使能器，光改 yml 不摘依赖，回退不彻底。本轮将该依赖整段移除，达成**全仓库 ADR I-2 真正 100% 闭环**。

### 2.3 必需改动 —— GAP-M2：移除 Backend 子模块 pom 的 prometheus 依赖（使能器）

| 文件 | 行 | 改前 | 改后 |
|------|----|------|------|
| `observability/backend/pom.xml` | 49-53 | 整段 `<dependency>`：`io.micrometer` / `micrometer-registry-prometheus` / `scope: runtime` | **删除整段** |

- 前置核查：Grep Backend 源码 `src/main/java` 下 `io.micrometer.prometheus` → **无匹配**，故直接移除依赖即可，无需清理源码引用。
- 保留项：`micrometer-core`（经 `spring-boot-starter-actuator` 传递引入，依赖树仍在）、`micrometer-observation` 等核心依赖；OTLP 指标导出由 OTel javaagent 桥接（见 §3 依赖树核对说明），不依赖 `micrometer-registry-otlp`，故该 registry 亦不需在 pom 中声明（原 pom 本就无此项）。

### 2.4 注释澄清核查 —— ADR I-3 范围（非必须，按指示先 Read 再决定）

- 核查文件：`src/main/java/com/mobileagent/app/observability/MetricsRegistry.java`
