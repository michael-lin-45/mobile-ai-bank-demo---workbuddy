## 5. 待确认问题（W3 启动前需敲定）

> 原则：能由现有文档/代码推断的已给结论并标注依据；仅列推断不出或需决策的项。

**Q1（需决策，Backend/QA 协同）— TC-E-002 的 H2 直查机制**
- **推断结论**：项目**无 test 侧 H2/JDBC 配置**（`common.py` 仅用 HTTP `requests`，无 JDBC 驱动/helper）；后端 DB 为 `jdbc:h2:file:./data/observability;MODE=MySQL;DATABASE_TO_LOWER=TRUE`（`application.yml:9`），**file 模式、无 `AUTO_SERVER`**（依据 `backend.log` 连接串）。因此 Python 测试若并行直连同一文件库会在后端运行时触发「database already in use」锁。
- **待决策（二选一）**：
  - **(a) 推荐**：后端新增一个**只读诊断端点**（如 `GET /api/v1/admin/diagnostics/dead-keys`，复用现有 `DataSource` 直查 `redis_metrics_snapshot` 并返回 5 死 key 计数），测试脚本改为调该端点断言 `count==0`。符合「复用项目已有 DB 连接配置」，无文件锁问题，改动小。
  - **(b) 备选**：后端 JDBC URL 加 `;AUTO_SERVER=TRUE`（混合模式），Python 侧用 JayDeBeApi + H2 jar 经自动 TCP 连接。需改配置 + 新增测试 JDBC helper。
- **建议**：W3 启动前由团队确认采用 (a) 或 (b)。
