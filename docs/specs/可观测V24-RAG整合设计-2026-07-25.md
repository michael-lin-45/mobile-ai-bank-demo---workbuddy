# 可观测 V24 — RAG 检索质量 Tab 整合设计方案

> 产品经理：许清楚（software-product-manager）｜日期：2026-07-25
> 输入：`RagPanel.jsx`、`可观测DEMO-v24-WorkBuddy.html`（L795–844 / L1109–1111 / L204–229）、`mockInsights.js getRagMock()`、`ExternalCallTab.jsx`，以及用户反馈（主理人转述）。
> 目标：RAG tab 最终呈现 **对齐 DEMO v24**，且 **前端与 DEMO 双端一致**（落地样式、内容、布局、视觉 token 全一致）。

## 1 问题陈述：当前前端 RAG tab 两块重叠的根因

当前 `RagPanel.jsx` 在 RAG tab 内渲染了**两个内容高度相似的模块**：

| 模块 | 当前渲染内容 | 数据来源 | 与 DEMO 的关系 |
|------|--------------|----------|----------------|
| **模块 A `RagRealContent`** | 4 个 Statistic（调用次数 / 平均耗时 / P95 耗时 / 错误率）+ 每检索器明细表（检索器/调用/成功/失败/平均/P95/错误率） | 真实 `fetchInvocations('rag')` 聚合 | **DEMO 中不存在于 RAG tab**；它等价于 DEMO「全部」视图的统一调用记录表（L807–814） |
| **模块 B `RagQualitySection`** | 5 子指标 KPI + 趋势图 + 检索质量子面板（Top-K 图 / 质量判定表） | 设计真值 `getRagMock()` | 对应 DEMO 的 3 块结构（运行态 5 KPI + 趋势 + 效果态子面板） |

**根因**：两块都含「调用 / 时延 / 错误率」类指标 → 用户感知为「两套统计、冗余」。

对照 DEMO 的 RAG tab，它**只有 3 个清晰块**（用户确认这是「对的」设计）：
1. **5 子指标 KPI = 运行态监控**（时延 / 触发率 / 错误率）—— 看「系统稳不稳」
2. **趋势图 = 5 子指标近 6h**
3. **检索质量子面板 = 效果态评估**（命中率 / 相关性 / 重排增益）—— 看「检索准不准」

DEMO 明确说明（L843）：*「5 子指标 = 运行态监控；检索质量子面板 = 效果态评估。二者视角不同、不重叠。」* 即运行态与效果态是**两个正交视角**，不是两套重复统计。

而模块 A 的「基础调用统计 + 明细表」在 DEMO 里属于「全部」视图的统一调用记录表，**不应在 RAG tab 重复出现**。前端因为复用了 `fetchInvocations('rag')` 的真实 rows 做聚合，误把「运行态」实现成了「调用明细表」，与 DEMO 的运行态（5 子指标 KPI）口径错位。

> 补充事实：`ExternalCallTab.jsx` 的「全部」segment 已渲染 `<InvocationTable dataSource={all} showCategory />`，即统一调用记录表已存在（对齐 DEMO L807–814）。故移出 RAG tab 后数据不丢失。

## 2 最终呈现设计（对齐 DEMO）

### 2.1 RAG tab 最终由 3 块组成

> 移除模块 A；仅保留与 DEMO 一致的 3 块。外层不再用单一「RAG 检索质量」Card 双重包标题，改为直接渲染 3 个带 DEMO 标题的子 Card（对齐 DEMO 的 3 个 `.card`）。

| # | 块中文标题（对齐 DEMO） | 性质 | 数据来源 | 角标策略 |
|---|--------------------------|------|----------|----------|
| ① | 📊 **RAG 运行指标（5 子指标）** ｜ 副标题：dev 链路真值 · 近 6h | 运行态（系统稳不稳） | **设计真值** `getRagMock().run` | 整块挂 `DemoBadge`（5 子指标后端未提供，Q7） |
| ② | 📈 **趋势图 · 5 子指标（近 6h）** | 运行态趋势 | **设计真值** `getRagMock().run.trend` | 随 ① 同属设计真值，挂 `DemoBadge` |
| ③ | 🔬 **RAG 检索质量子面板** ｜ 左：Top-K 相关性分布 ／ 右：质量判定表 | 效果态（检索准不准） | **设计真值** `getRagMock().quality` | 整块挂 `DemoBadge` |

### 2.2 块①：5 子指标 KPI（运行态）指标清单

| 指标名 | 口径 | 单位 | 数据来源 | DEMO 值 | KPI 副文案（k-sub，需补） |
|--------|------|------|----------|---------|---------------------------|
| 重排时延 P95 | reorder 阶段时延 P95 | ms | 真值 `run.reorderP95Ms` | 45 | ↓ 12.4% 较昨日 |
| 平均召回文档数 | 每次 RAG 平均召回文档数 | 篇 | 真值 `run.recallDocs` | 8.2 | ↑ 0.6 篇 |
| RAG 触发率 | 含检索会话占比 | % | 真值 `run.triggerRate` | 64 | ↑ 3.1% 会话含检索 |
| 检索错误率 | retrieve 阶段错误率 | % | 真值 `run.retrieveErrRate` | 0.4 | ↓ 0.1% 网络/超时 |
| 重排错误率 | reorder 阶段错误率 | % | 真值 `run.reorderErrRate` | 0.1 | → 持平 |

> 说明：5 子指标目前**全部为设计真值**（后端无 5 子指标结构，见设计文档 Q7）。因此块①必须挂 `DemoBadge` 以避免误导；副标题文案与 DEMO 一致写为「dev 链路真值 · 近 6h」。

### 2.3 块②：趋势图（5 子指标近 6h）

- 类型：ECharts 折线，5 条 series。
- series 与配色（对齐 DEMO L1110）：重排时延P95 `#08979c` / 召回文档数 `#13c2c2` / RAG触发率 `#722ed1` / 检索错误率 `#ff4d4f` / 重排错误率 `#faad14`。
- 双 Y 轴：左轴 `ms / 篇`，右轴 `%`（DEMO 双轴配置）。
- x 轴：10:00–16:00（7 点）；数据取自 `run.trend`（与 DEMO 完全一致）。

### 2.4 块③：检索质量子面板（效果态）

**左：Top-K 相关性分布（`RagQualityChart`，`quality.topK`）**
- series：Top-1 / Top-3 / Top-5（颜色 `#08979c` / `#13c2c2` / `#722ed1`）。
- x 轴：07-04 / 07-06 / 07-08 / 07-10；y 轴：%，max 100。
- 数据 `quality.topK`（前端现有，与 DEMO L1111 一致，**无需改**）。

**右：质量判定表（`quality.table`）—— 统一以 DEMO 为权威口径**

| 质量维度 | 当前值 | 目标 | 判定（DEMO 权威值） | 前端渲染 |
|----------|--------|------|---------------------|----------|
| Top-1 命中率 | 52% | ≥60% | 偏低 | `Tag color="gold"`（warning） |
| Top-5 命中率 | 64% | ≥70% | 偏低 | `Tag color="gold"`（warning） |
| 平均相关性评分 | 0.82 | ≥0.85 | 临界 | `Tag color="gold"`（warning） |
| 空召回率（无文档） | 1.2% | ≤2% | 达标 | `Tag color="green"`（success） |
| 重排提升度（NDCG@5） | +0.11 | ≥+0.08 | 达标 | `Tag color="green"`（success） |

> ⚠️ **关键不一致（必须修）**：当前前端 `getRagMock().quality.table` 是 **6 行且全部「good」**（含 Top-3 命中率行、NDCG@5 写成绝对 `0.79`、各目标阈值更宽松），与 DEMO 的 5 行「偏低/临界」严重不符，会**误导**用户以为检索质量全达标。落地须以本表（DEMO）为唯一真值，前端改 `getRagMock` 对齐（见 §4 F2）。
> 注：DEMO 此表**不使用红色**（无 error 级判定），未达标一律用金色 `warning`；前端须同步，不可渲染红色。

### 2.5 关键决策：基础调用明细表（模块 A）处理结论

**结论：RAG tab 不展示该明细表，从 `RagPanel` 移除 `RagRealContent`。**

- 理由：该「基础调用统计 + 每检索器明细表」在 DEMO 中属于「全部」视图的统一调用记录表（L807–814），不属于 RAG tab；前端「全部」segment 已通过 `InvocationTable` 承载，数据不丢。
- 若需保留「运行态」观感：**块① 5 KPI + 块② 趋势图已完整覆盖运行态视角**，无需额外明细表。
- 真实 `fetchInvocations('rag')` 数据去向：仅用于「全部」视图统一表；RAG tab 始终以设计真值 3 块呈现（除非后端接入 5 子指标/质量真值，见 §6 Q1/Q2）。
