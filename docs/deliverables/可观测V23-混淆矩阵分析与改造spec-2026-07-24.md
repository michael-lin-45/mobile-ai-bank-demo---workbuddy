### 1.2 三方案样式对比表

| 维度 | V16 DEMO | V23 DEMO | 前端当前 |
|---|---|---|---|
| 主色 | 灰→蓝单调（`#f5f5f5`→`#1677ff`） | jet 彩虹（蓝→青→黄→红），含**红金** | 灰→蓝（同 V16 配置） |

### 1.3 前端当前实现逻辑 bug 清单（逐条，带行号）

> 文件：`observability/frontend/src/components/charts/HeatmapChart.jsx`

**BUG-1 · visualMap 量程与数据量级不匹配 —— "全部灰色 / 没有重点" 的根因**
- 位置：L72-79（`min:0, max:100` + `color:['#f5f5f5','#1677ff']`）。
- 事实：该配置是**照搬 V16 的 0–100 百分比量程**，但前端实际接入的 `confusion.matrix` 是 **原始计数**（`mockInsights.js` L123-129，值 8–980；真实后端亦应为计数）。
- 后果：① 对角线（760–980）与较大混淆格（理财咨询↔理财解读 的 140/130）全部被 clamp 到 `#1677ff`，小混淆格（8–25）落在浅灰端 → 0–100 渐变完全失效，变成"蓝/灰"二值，**失去混淆严重度的视觉编码**；② 视觉"重点"错误地落在正确分类的对角线，而非运营关心的混淆格 → 用户感知"没有重点"。

**BUG-2 · Y 轴反转但数据未同步补偿 —— 坐标轴 / 维度搞反**
- 位置：L67 `yAxis:{ data: labelsY.reverse(), ... }` 将 Y 类别倒序（标签 0 落到底部）；但真实数据路径 L26-32 `heatData.push([colIdx, rowIdx, value])` 用**原始 `rowIdx`**，未补偿。
- 事实：V16（L672）与 V23（L1067）**均未反转 Y 轴**，数据 `[x=j, y=i]` 与轴一一对应。前端多加了 `.reverse()` 却没改数据 → 与 V16/V23 都不符。
- 后果：因 `AccuracyTab.jsx` L134 总是传入 `matrix`，走真实数据路径 → **矩阵被上下翻转**，对角线错位到错误象限，行标签与数据错配。

**BUG-3 · 真实数据 / 默认数据两条路径不一致（BUG-2 的延续）**
- 位置：L37-38 `defaultData = heatData.length>0 ? heatData : buildDefaultData(labelsX)`；`buildDefaultData` 在 L124 用 `size-1-i` 补偿了反转，而真实路径（L26-32）没有。
- 后果：一旦传入 matrix 永远走未补偿的 `heatData`，`buildDefaultData` 实为死代码；两条路径对 Y 向处理互逆，是 BUG-2 的直接成因。

**BUG-4 · Tooltip 箭头方向写反（语义错位）**
- 位置：L48 `` `${labelsX[p.data[0]]} → ${labelsY[p.data[1]]}` ``。
- 事实：区块约定"**行=预测 · 列=实际**"（x=列=实际，y=行=预测）。当前把"实际 → 预测"呈现，与"预测 X 被误判为实际 Y"的直觉相反，应为 `labelsY[row] → labelsX[col]`（预测→实际）。`diag = x===y` 仍成立，但文案方向误导。

**BUG-5 ·（次要）对角线无差异化强调**
- 位置：L84-88 label 统一 `rgba(0,0,0,.65)`，无"✓"或混淆高亮。叠加 BUG-1 失效渐变，进一步导致"无重点"。

> 附：V23 DEMO 混淆矩阵自身问题（融合时规避）
> - L1067 `visualMap` 无 `inRange.color` → 默认 jet 红金（用户吐槽来源）。
> - L1067 data 含 `[0,6,2]`：x 索引 6 超出 xAxis 6 类别(0–5) → 该格被丢弃/错位（数据 bug）。
> - 英文标签 + 6 意图（含 UNSUP）与平台中文 5 意图不一致；稀疏三元组可读性差。

### 1.4 融合推荐设计（V16 美观 + 正确 + 突出混淆）

**一句话：采用 V16 的中文标签 + 灰→蓝单调渐变基调（按行归一化到 0–100% 让量程正确生效），叠加对 top-N 混淆格的暖色描边/加粗强调（不照搬 V23 红金满铺），并修复 Y 轴翻转与 tooltip 方向 bug。**

1. **数据契约不变，组件内做行归一化**：`confusion = { labels: string[], matrix: number[][] }`，`matrix[row=预测][col=实际]` 为原始计数。组件内部按行求和，计算 `pct = count / rowSum * 100` 用于上色；tooltip 同时展示 count 与 pct。→ 量程 0–100 终于生效（对齐 V16）。
2. **配色（V16 基调）**：`visualMap:{ min:0, max:100, show:false, inRange:{ color:['#f5f5f5','#1677ff'] } }`。对角线（~88–98%）深蓝＝"正确质量"，浅蓝/灰＝低混淆。
3. **突出混淆（融合增强，不用红金满铺）**：对**非对角线**且 `pct ≥ 阈值(建议 5%)` 或 **top-N 混淆格**，用 `itemStyle` 覆盖：暖色描边 `#fa8c16`/文字加粗、`#ff4d4f` 用于最严重的 1–2 对；对角线保持蓝阶 + 轻量"✓"角标。既保留 V16 冷静基调，又让运营一眼看到"重点"。
4. **Tooltip**：`预测 {pred} → 实际 {act}`（修 BUG-4），显示 `✗ 混淆 N 例 (P%，占预测为 {pred} 的 P%)` / 对角线 `✓ 正确分类 N 例 (P%)`。
5. **坐标轴（修 BUG-2/3）**：`yAxis:{ type:'category', data: labelsY, inverse:true }`（标签 0 置顶，常规混淆矩阵朝向），**删除 `labelsY.reverse()`**；真实数据与默认数据统一用 `[colIdx, rowIdx, value]`（删除 `buildDefaultData` 的 `size-1-i`）。
6. **Legend / 说明**：矩阵下方加一行小字说明"单元格颜色 = 该预测意图下、实际为各意图的占比（行内归一化）"，并可选列出 top-2 混淆对（如 `⚠ 主要混淆：理财咨询↔理财解读 13%/12%`）作为 caption——直接服务"找混淆"目标。
7. **标签语言**：中文意图（与 V16/前端一致，不用 V23 英文）。

可直接复用的推荐 ECharts option 见文末附录 §3。

### 3.2 混淆矩阵推荐 ECharts option（前端 / DEMO 可直接复用）

```js
function buildConfusionOption(labels, matrix) {
  const n = labels.length;
  const data = [];
  // 行归一化：pct = count / rowSum * 100
  matrix.forEach((row, i) => {
    const rowSum = row.reduce((a, b) => a + b, 0) || 1;
    row.forEach((v, j) => {
      const pct = +((v / rowSum) * 100).toFixed(1);
      const isDiag = i === j;
      const isTopConfuse = !isDiag && pct >= 5; // 混淆重点
      data.push({
        value: [j, i, pct],            // x=实际(col), y=预测(row)
        // 非对角线且≥5%：暖色描边强调（不整片红金）
        itemStyle: isTopConfuse
          ? { borderColor: pct >= 10 ? '#ff4d4f' : '#fa8c16', borderWidth: 2 }
          : undefined,
        label: {
          show: true, fontSize: 10,
          color: isDiag ? 'rgba(0,0,0,.65)' : (isTopConfuse ? '#d4380d' : 'rgba(0,0,0,.45)'),
          fontWeight: isTopConfuse ? 700 : 400,
          formatter: () => `${v}\n${pct}%`,
        },
        _count: v, _pct: pct, _isDiag: isDiag,
      });
    });
  });
  return {
    tooltip: {
      position: 'top',
      formatter: (p) => {
        const d = p.data;
        const pred = labels[p.data.value[1]], act = labels[p.data.value[0]];
        return d._isDiag
          ? `✓ 正确分类<br/>预测 <b>${pred}</b> → 实际 <b>${act}</b><br/>${d._count} 例 (${d._pct}%)`
          : `✗ 混淆<br/>预测 <b>${pred}</b> → 实际 <b>${act}</b><br/>${d._count} 例 (占预测为${pred}的 ${d._pct}%)`;
      },
    },
    grid: { left: 60, right: 15, top: 10, bottom: 25 },
    xAxis: { type: 'category', data: labels, position: 'top', axisLabel: { fontSize: 10 }, axisLine: { show: false }, axisTick: { show: false } },
    yAxis: { type: 'category', data: labels, inverse: true, axisLabel: { fontSize: 10 }, axisLine: { show: false }, axisTick: { show: false } },
    visualMap: { min: 0, max: 100, show: false, inRange: { color: ['#f5f5f5', '#1677ff'] } },
    series: [{ type: 'heatmap', data, emphasis: { itemStyle: { shadowBlur: 10, shadowColor: 'rgba(0,0,0,.15)' } } }],
  };
}
```

> 关键修复点对照：① `inverse:true` + 删除 `.reverse()`（修 BUG-2/3）；② 用 `pct`（0–100）上色使量程生效（修 BUG-1）；③ 暖色描边仅作用于 top 混淆格（突出重点，不照搬 V23 红金）；④ tooltip `预测→实际` + count/pct（修 BUG-4）。
