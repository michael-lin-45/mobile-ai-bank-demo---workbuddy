### 3.2 关键过程事实（含主理人交叉核验与一次返工）

- **首轮交付存在遗漏**：工程师首轮仅改了 #1（Backend yml:79），并额外发现两个 Core profile 配置仍违规暴露 prometheus（#3/#4，主理人裁定属回退范围并指令收口）。
- **主理人交叉核验抓出 GAP-M2 未闭环**：汇编前主理人对工程师「IS_PASS=YES / ADR I-2 100% 闭环」结论做了 Grep 实锤，发现 `observability/backend/pom.xml:51` **仍残留** `micrometer-registry-prometheus` 依赖——而 relay 中明确要求一并移除。工程师原报告 §2/§5 对该依赖只字未提，属**报告与事实不符**。
- **二次返工闭环 GAP-M2**：主理人将工程师叫回，补全 #2（移除 Backend pom 依赖）。前置核查 Backend `src/main/java` 下 `io.micrometer.prometheus` 引用 **0 匹配**，故直接删依赖；Backend 重编 EXIT=0；`dependency:tree | grep prometheus` **0 匹配**；全仓 `micrometer-registry-prometheus` Grep **0 匹配**（已主理人复验确认）。
- **结论**：配置层（4 个 yml 无 prometheus 端点暴露）+ 依赖层（两 pom 无 prometheus 依赖）双双清零，ADR I-2 真正 100% 闭环。
