### start-all.ps1 启动顺序修复: Backend "FATAL: 已挂" 问题
- **根因**: 脚本启动顺序是 Backend→Collector，Collector 60×2s 等待循环中检查 Backend 是否存活。Backend Java 进程在等待窗口内被沙箱杀掉（AppData\Crypto\RSA 拦截），脚本检测到 Backend DOWN 后错误地 FATAL 退出
- **误解**: Collector 不需要 Backend 先启动！OTel Collector exporter 是懒连接，先监听 4318，数据到来时才转发到 Backend
- **参考**: 外部 `mobile-ai-bank-demo - local/observability/scripts/start-all.ps1` 使用的是 Collector→Backend 顺序
- **修复**: 交换步骤 2/3，改为 Collector(2)→Backend(3)，移除 Collector 等待循环中对 Backend 存活的假依赖检查

### Collector 端口 8888 僵尸进程问题
- **第一版修复失效**: `Stop-Port 4318; Stop-Port 8888` 仍有竞态——先杀 4318 上的进程后 OS 未及时释放 8888，第二个 Stop-Port 查不到进程，新 collector 启动时 8888 仍被占用
- **第二版修复**: 改为先 `Get-Process -Name otelcol | Stop-Process`（按进程名杀），再循环等待两个端口都释放（最多 15s），彻底消除竞态
