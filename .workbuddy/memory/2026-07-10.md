## R27 — Core 侧 L1 层 intent 回流 span（用户"这个开始修复"）

### 目标
让 #2 意图链显示完整 L1 层识别结果（如 `WEALTH Domain→SWITCH→wealth-filter→WealthConsultGraph`）。
R26 时因 Core 未把 L1 层 intent 写入 span，#2 仅能显示 `WEALTH Domain` 段，取不到 SWITCH/wealth-filter。

### 根因（机理）
`ObsChatModel.call()` 在 `delegate.call()` 返回后立即于 `finally` 里 `span.end()`；而 L0/L1 的识别结果（domain / routeType / intentName）是在 LLM 返回后由 router 解析出的 → span 已 end，结果来不及写入。

### 修复：托管 span（held-span + commit）
- `AgentSpanContext`：新增 `setWithHeldSpan(layer,name,intent,...)`（置 holdSpan=true）、`attachSpan(span)`（ObsChatModel 创建 span 后回挂引用）、`commitIntent(intent, extra)`（回填 intent 属性并 end span，isRecording()=false 时安全 no-op）、`isHoldSpan()`；字段 `holdSpan` / `liveSpan`。
- `ObsChatModel.call()`：若 ctx.holdSpan → 创建 span 后 `attachSpan` 且 `finally` **不自动 end**（交 router commit）；异常路径仍 self-end 防泄漏，并提交 `ended` 标志避免重复 end。
- `DomainRouter` / `ContextRouter` / `SubGraphRouter`：改用 `setWithHeldSpan`；解析出真实结果后 `commitIntent`（L0=domain / L1-LLM1=routeType / L1-LLM2=intentName）；LLM 调用失败的内层 catch 也 commit 兜底。
- **泄漏兜底**：三 router 最外层 try 后补 `finally { AgentSpanContext.clear(); }`，覆盖"LLM 成功但后续埋点/状态更新异常"导致未 commit 的边界——正常路径 commitIntent 已 remove ThreadLocal，clear 为 no-op，安全。
