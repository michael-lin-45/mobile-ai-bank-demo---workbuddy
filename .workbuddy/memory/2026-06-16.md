## start-core-only.ps1 启动失败排查与修复（完整版）

### 根因链（共 3 层）

**L1: Maven Wrapper cache hash 不匹配**
- `mvnw` (sh): 使用 Java hashCode → `9925cc1d`
- `mvnw.cmd` (PowerShell): 使用 SHA-256 → `0226a00282e40018...`
- 缓存目录名: SHA-256 → 只有 .cmd 能找到，shell 脚本找不到
- Fallback 到网络下载 → 下载失败
- **修复**: 创建 symlink `9925cc1d` → `0226a00282e40018...`

**L2: Maven mvn 脚本 MinGW 路径转换缺失**
- Git Bash/MinGW 运行 mvn 时，`MAVEN_HOME` 被转为 Unix path (`/c/Users/...`)
- 但传给 Java 的 `-classpath` 未转为 Windows 格式
- Java 无法识别 `/c/` 路径 → `ClassNotFoundException: Launcher`
- Cygwin 有 `cygpath` 转换，MinGW 没有
- **修复**: 在 `mvn` 脚本中添加 MinGW 路径转换块（cygpath 在 Git Bash 中可用）

**L3: logback-spring.xml 引用未加载的 OTel Appender**
- `logback-spring.xml` 引用 `OpenTelemetryAppender`
- 该类在 `opentelemetry-javaagent.jar` 中，但 agent 未作为 javaagent 加载
- ClassNotFoundException → Spring Boot 启动崩溃
- **修复**: 
  - pom.xml: 添加 `-javaagent` 参数（含路径加引号处理空格）
  - logback-spring.xml: OTLP appender 改为 springProfile="otel"，默认不加载

### 修改文件清单
1. `C:\Users\Administrator\.m2\wrapper\dists\...\bin\mvn` — MinGW 路径转换
2. `C:\Users\Administrator\.m2\wrapper\dists\...\9925cc1d` — symlink 到 SHA-256 目录
3. `pom.xml` — `-javaagent` + `-Dserver.port=8080`（含引号处理空格）
4. `logback-spring.xml` — OTLP appender 条件化
5. `start-core-only.ps1` — 绕过 mvnw wrapper（备用方案）

### 验证结果
- `./mvnw compile` → BUILD SUCCESS
- `./mvnw spring-boot:run` → Tomcat started on port 8080, Started MobileAiDemoApplication in 7.6s
- OTel 连接 4318 失败仅为本地无 collector（预期行为，不影响功能）
- 注意: Maven 退出后 Java 子进程可能残留，需手动 `Stop-Process -Id <PID>` 释放端口

## Redis 健康检查告警
开发环境无 Redis，但 `RedisReactiveHealthIndicator` 每隔几秒尝试连接 localhost:6379 → 持续 WARN 日志。

**坑点**: 之前把 `management.health.redis.enabled: false` 放在 `spring:` 子节点下 → Spring Boot 读不到，必须是顶级 `management:` 节点！

正确结构：
```yaml
# 必须在顶级，不能在 spring: 下面
management:
  health:
    redis:
      enabled: false
```

验证: `GET /actuator/health` 返回 `{"status":"UP"}`，无 Redis 字段，不再有 RedisReactiveHealthIndicator WARN。


## start-all.ps1 运行排查（3 个问题）

### P1: 可观测后端端口不一致

**根因**: 项目有 2 个后端入口 — `src/index.js`(Express/9090) 和根目录 `index.js`(原生http/9092)
- `package.json` 的 `"main":"index.js"` + `npm run dev` 实际跑 9092 版本
- 脚本用 `$OBS_PORT=9090` 检查 → 永远等不到
**修复**: `$OBS_PORT=9092`，启动命令改为 `node index.js`(根目录)

### P2: localhost = IPv6 导致连接超时

**根因**: `Invoke-WebRequest "http://localhost:9090/health"` 解析为 IPv6 `::1`
- 后端 `server.listen(PORT, '0.0.0.0')` 只绑 IPv4 → IPv4↔IPv6 不通
**修复**: 所有健康检查 URL 改为 `http://127.0.0.1:$PORT/...`

### P3: 核心启动命令嵌套引号爆炸

**根因**: 三层引号嵌套 + 路径含空格 → PowerShell 解析失败 → 新窗口瞬间退出
**修复**: Base64 UTF-16LE + `-EncodedCommand`，remove agent param(pom.xml 已内置)，cd + mvnw.cmd

```powershell
$coreCmd = "cd '$CORE_PROJECT_PATH'; .\mvnw.cmd spring-boot:run"
$coreBytes = [System.Text.Encoding]::Unicode.GetBytes($coreCmd)
$coreB64 = [Convert]::ToBase64String($coreBytes)
Start-Process powershell -ArgumentList "-NoExit", "-EncodedCommand", $coreB64
```

## SseAdapter 500 错误修复

**症状**: `HttpMessageNotWritableException: No converter for [WorkflowOutput] with preset Content-Type 'null'`

**根因**: `SseOutputAdapter.toJson()` 返回类型为 `Object`
- `.block()` 返回 `WorkflowOutput`，但方法签名 `Object` → Spring MVC 推断 Content-Type 为 null
- `HttpMessageConverter` 匹配失败 → 500

**修复**: 返回 `ResponseEntity<WorkflowOutput>`，显式设置 `Content-Type: application/json`
```java
public ResponseEntity<WorkflowOutput> toJson(Flux<StreamChunk> pipeline) {
    WorkflowOutput output = pipeline...block();
    return ResponseEntity.ok().contentType(MediaType.APPLICATION_JSON).body(output);
}
```

**规则**: 配置、脚本、API 调用中的 `localhost` 全部用 `127.0.0.1`
