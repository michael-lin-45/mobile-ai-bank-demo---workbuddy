## R41 — V5 银行业务量级修正
- 用户补充背景：银行业务系统，静态用户量数千万级。
- V4 的 6 项 Demo 假设在银行量级下失效，需升级：
  | Demo 假设 | 银行量级现实 | V5 修正 |
  |---|---|---|
  | H2 P2 才迁 PG | 独占锁+单文件，数亿条数据直接崩溃 | **P0 即迁 PostgreSQL**（分区表+DROP PARTITION+PgBouncer） |
  | Redis 单实例 | SPOF + HyperLogLog 3000万用户误差±24万 | **Sentinel HA + DAU 改 Bitmap**（精度100%，3.6MB） |
  | Collector 单机 | 每日数亿次对话→OOM+SPOF | **3 实例集群 + Nginx LB** |
  | 10% 正常采样 | 亿级×10%=存储爆炸 | **降为 1%**（错误/慢/LLM失败仍100%保留） |
  | 7 天清理 | 银保监要求 3-7 年审计轨迹 | **分层保留：热7d PG→温90d PG压缩→冷3y 对象存储** |
  | 5min 告警抑制 | 量级下异常波动告警风暴风险放大100× | **加收敛窗口 5min + 静默期 30min（连续3次触发自动静默）** |
- 不受影响的组件选型：Tempo/VM/Loki/Grafana 对象存储后端天然适合海量数据，选型依然最优。
