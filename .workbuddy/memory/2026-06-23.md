### start-all.ps1 路径空格 → EncodedCommand 修复
- **问题**: 运行 `.\observability\scripts\start-all.ps1` 报 `Unable to access jarfile D:\GitHub\mobile-ai-bank-demo`，Java 只收到路径空格前的部分
- **根因**: 工作区路径 `D:\GitHub\mobile-ai-bank-demo - workbuddy` 含空格，脚本中 4 处 `Start-Process` 使用 `-ArgumentList` + 嵌套双引号传参，引号在多层解析中失效，路径被空格截断
- **修复**: 4 处全部改用 Base64 UTF-16LE + `-EncodedCommand`（项目既有惯例），彻底绕开嵌套引号问题
  - Backend:9090 (line 48)
  - Collector:4318 (line 57)  
  - Core:8080 (line 69)
  - Frontend:3000 (line 78)

### 第二轮修复：Base64 命令中单引号改双引号（仍失败）
- **问题**: 第一次 EncodedCommand 修复用了单引号 `'$PATH'`，Core:8080 启动时报 `找不到或无法加载主类 .exporter.otlp.endpoint=http:..127.0.0.1:4318`，`-jar` 路径因空格截断导致 `-Dotel` 被当作主类名
- **根因**: 单引号在 Base64 → EncodedCommand → 新窗口执行的链路中，对含空格路径的保护不如双引号可靠
- **修复**: 全部改成 `` `"$PATH`" ``（反引号转义的双引号）
- **结果**: 仍然失败，双引号版本同样在 EncodedCommand 链路中存在参数解析问题

### 第三轮修复：彻底放弃嵌套 PowerShell，用数组 ArgumentList
- **根因再分析**: EncodedCommand 这条路本身就不可靠——无论单引号还是双引号，经过 Base64 编码 → 子 PowerShell 解码 → 再执行的链路后，含空格、含 `:` 和 `//` 的 Java 参数总会被错误分割
- **最终方案**: `Start-Process` 直接用目标进程（java/npm/otelcol），`-ArgumentList` 用数组形式，PowerShell 原生自动为含空格参数加引号；用 `-WorkingDirectory` 替代 `cd`
  - Backend: `Start-Process java -ArgumentList @("-jar", $BACKEND_JAR, ...) -WorkingDirectory $ROOT`
  - Core: `Start-Process java -ArgumentList @("-javaagent:$AGENT", "-Dotel...", "-jar", $CORE_JAR, ...) -WorkingDirectory $ROOT`
  - Collector: `Start-Process $COLLECTOR -ArgumentList @("--config", $COLLECTOR_CFG) -WorkingDirectory $ROOT`
  - Frontend: `Start-Process $npm -ArgumentList @("run", "dev") -WorkingDirectory $FRONTEND`
  - 注: Frontend 仍失败（npm.cmd 需在 shell 中跑），改回 `powershell -NoExit -Command "cd '...'; npm run dev"`

### 第四轮：健壮健康检查 + Fail Fast
- **问题**: 4 个服务启动后的健康检查循环跑完重试次数就默默继续，不校验是否真的起来了；Backend/Core 超时后脚本仍继续启动后续服务
- **修复**: 新增 `Await-Service($label, $port, $healthUrl, $maxRetry, $sleepSec)` 函数，返回 `$true/$false`；每个服务调用后 `if (-not) { pause; exit 1 }` 即时终止
- 同时给出每个服务失败时的具体诊断提示（检查窗口日志 / 配置有效性 / node_modules 等）

### 第五轮：含中文 .ps1 缺少 BOM 导致解析乱码
- **问题**: 脚本反复报"字符串缺少终止符""语句块缺少右}"等语法错误，且每次错误行号不同
- **根因**: 文件 UTF-8 无 BOM → Windows PowerShell 5.1 按系统 ANSI(GBK) 解码 → 中文字符变成乱码 → 破坏引号/括号边界
- **修复**: 文件头部加 UTF-8 BOM（EF BB BF），PowerShell 识别到 BOM 后按 UTF-8 正确解析
- 已更新 MEMORY.md 新增规则：**所有含中文的 .ps1 文件必须存为 UTF-8 with BOM**
