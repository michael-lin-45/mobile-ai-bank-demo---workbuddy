## P0-Part5: H2 连接池打爆紧急修复 (22:07)

### 现象
- HikariPool-1: Connection is not available (active=10, waiting=68)
- 前台所有 API 超时 (10000ms)

### 根因
MetricsQueryService.getRealtime() 的 H2 回退查询每 3 秒轮询触发一次，`findByTimestampBetweenOrderByTimestampAsc(from, to)` 对 239MB 的 metrics_agg 表做全表扫描，锁住连接池所有连接。

### 修复
1. 添加 H2 回退节流：距上次回退 ≥ 60s 才再次执行（lastFallbackMs）
2. 删除所有全表扫描方法：`sumMetricValueLike`、`avgMetricValueLike`、`aggregateAgentLayer`
3. 全部改为按 metricName 的索引查询 (`findByMetricNameAndTimestampBetween`，命中 idx_metrics_name_ts)
4. 时间窗口从 24h 缩到 1h
5. 删除 agent layer / TTFT 的 H2 回退（精确 tag 聚合仍需要全表扫描，暂不实现）
